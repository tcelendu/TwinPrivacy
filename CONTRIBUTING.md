# Contributing to TwinPrivacy

Contributions to reproducibility, privacy modeling, healthcare semantics,
accessibility, and security review are welcome.

Before proposing a change:

1. Run `python reproduce.py` and verify that the test suite succeeds.
2. Include tests and an updated method description for behavioral changes.
3. Record the provenance, permissions, and reuse licence of any new dataset.
4. Keep observed clinical findings separate from generated examples.
5. Do not submit identifiable patient records, access credentials, or sensitive
   disclosure logs in issues, pull requests, or public sample data.
6. Do not imply that an internal hash chain establishes complete auditing,
   that conditional surprisal is a formal privacy budget, or that the
   analysis has been clinically validated without independent evidence.

The maintainers will need to establish a code review and contribution
process once the repository is assigned to an owner.
